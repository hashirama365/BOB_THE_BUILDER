# ChangeGuard Brief — CG-103

## Emit Audit Events on Hold Status Transitions

**Status:** ⚠️ Prerequisites + coordination required

### Heads up
You are implementing an append-only audit log system for booking hold transitions. This task requires setting up a new SQLite table, creating an `auditLog.ts` module, and instrumenting existing booking endpoints to record status changes.

### Before you start

*   **CG-101 (Add Container Hold Status):** This ticket introduces the `/hold` and `/release-hold` endpoints you are required to instrument. You cannot implement the audit triggers until these routes exist. Verify that the request body and status fields in CG-101 provide the necessary context (before_status/after_status) before proceeding.
*   **CG-105 (Refactor Booking Cutoff Logic):** This ticket refactors core booking logic in `server/src/routes/bookings.ts`. Ensure this refactor is merged first to avoid working on outdated route handling code.

### Suggested dependency order
CG-105 ↓ CG-101 ↓ CG-103

### Where you'll probably be working
Your primary focus will be creating `server/src/audit/auditLog.ts` and updating the schema in `server/src/db/schema.sql`. You will also need to touch `server/src/routes/bookings.ts` to inject the audit events and `server/src/index.ts` to mount the new audit API.

> Tip: Treat these as starting points, not a fixed implementation plan. Verify the current code before making changes.

### Watch for collisions

*   **CG-101, CG-102, and CG-105:** All these tickets overlap heavily in `server/src/routes/bookings.ts`. Because you are adding hooks to the *same* endpoints these tickets are building or modifying, prioritize merging their changes first. Check if the refactoring from CG-105 has moved business logic into a helper; if so, you may be able to hook your audit calls there instead of manually editing every route.
*   **CG-104:** This ticket also touches `server/src/index.ts` to register routes. Expect a potential trivial merge conflict here when adding your new `/api/audit/events` route.

### What this means for you
Check the current state of `server/src/routes/bookings.ts` before starting, as it is a highly contested file. If CG-105 has been merged, leverage the new `BookingCutoffPolicy` or similar patterns to avoid duplicating status-check logic when emitting events. Sync with the owners of CG-101 and CG-102 to ensure your audit hooks don't break their hold/release workflows.
